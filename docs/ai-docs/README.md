Machine-oriented reference for **RED Modding Center v5.0** (RED MC) and the
NBA 2K13/2K14 file formats it edits. Generated by reverse engineering on
2026-08-02 from the installed copy at `C:\Editing Tools\RED MC` and from live
`.ROS` roster files in `%APPDATA%\2K Sports\NBA 2K14\Saves`.

## Key verified facts (TL;DR)

*Cross-checked 2026-09-26 against Roster Lab by Q2K 1.7.0 and
`FIBA 2017 SEABA.ROS`; see [09-roster-lab.md](09-roster-lab.md).*

- `.ROS` (NBA 2K14 PC) is a **fixed-size 2,672,672-byte** container; all
  integers **big-endian**.
- Offset `0x00` = **CRC32 (zlib polynomial) of bytes `0x04`..EOF**, stored
  big-endian. Recompute + rewrite it and the game/RED MC accept externally
  modified files (`ros_inspect.py resign`).
- Offset `0x04` = magic `50 15 51 AE`; `0x08` = format id (ROS 5, FXG 8,
  CMG 0x10, FDC 0x16); `0x0C` = file size; `0x18` = end-of-data pointer;
  `0x250`/`0x254` = string-heap next-free handles.
- `0x24..0x24B` = table **directory**: 46 × `{id 0x01xx, struct hash, value}`.
  **Off by one:** the hash belongs to `id`, but `value` is the record count
  of section `id+1`. Struct hashes match RED MC caption filenames
  (e.g. `Struct735767AE.txt`). The full section map (Players = **0x0103**,
  1665 × 3644 bits; Teams = 0x010A, 105 × 5764; …) is in
  [02-ros-format.md](02-ros-format.md).
- Table data is **one continuous bit-packed stream** from bit 4960 (byte
  0x26C). Sections come in stamp order with **fixed-width** records, each
  starting `[u16 stamp][u16 index]`. The phase differs per file because
  record counts differ, not because of strings.
- All strings are **null-terminated UTF-16BE in a heap after the last
  section**. Records hold **32-bit handles** (`[012F]`/`[0130]` + character
  offset), not indices into the name tables.
- References are `[u16 target stamp][u16 record index]` (e.g. player bit 192 =
  team).
- Field meanings for every table are fully enumerated in RED MC's own
  `Text/NBA2K14/Captions/*.txt` + `Text/Enums.txt` (parse rules in
  [03-data-dictionary.md](03-data-dictionary.md)).

- **Player records are 3644 bits (455.5 bytes)**, pre-allocated slots with
  their IDs stamped in; `record_bit = start(0103) + 3644 × index`. Mapped:
  height and weight (**big-endian IEEE-754 float32**, cm and lb), position,
  play style, jersey, birthdate, IDs, team references, contract years, and
  the 42-entry skill-rating array (8-bit, `raw = 3 × (displayed − 25)`, **storage
  order now known**). See [06-player-record-map.md](06-player-record-map.md).
- Crash rules any writer must respect: no all-zero player face block (bits
  388–415), name handles must hit a string start, and a team's 20 roster
  slots must be packed with `PlNum` in sync (09).
- RED MC ships an **official field specification** (a 77-page docx of
  1160 field rows with storage types and ranges) that answers most format
  questions directly — see [08-official-field-spec.md](08-official-field-spec.md).
- `roster.iff` (game default roster) = same table container, little-endian,
  zlib-compressed inside an IFF wrapper ([07-roster-iff.md](07-roster-iff.md)).

## What is NOT yet mapped (by us)

Roster Lab's correlation schemas place most fields of Players, Teams, Staff,
Stats, Team_Stats, Jerseys, Awards, Records, Trades and Headshapes. Use them
as a **cross-check only** (all-rights-reserved licence). Still open:

- Fields Roster Lab only bounds (`bmin`/`wmax`: 162 of 343 player fields).
  Pin them down with a bitdiff.
- Player_Ratings0–4 (011D–0121) and the claimed signed −128..127 fields.
- Sections 012B/012C/012E, most of the .FXG/.CMG tails, and the second team
  reference at player bit 2313 (meaning of any difference from the current
  team).


The proven method is **differential editing**: change exactly one field in
RED MC (or in-game), save, and run `ros_inspect.py bitdiff old.ros new.ros`.
Statistical validation over all ~1000 players (distributions, cross-field
correlations, encoding invariants like "all values are multiples of 3")
confirms a candidate far more reliably than matching a handful of stars — see
[06-player-record-map.md § Methodology](06-player-record-map.md#reproducible-methodology-what-worked).
